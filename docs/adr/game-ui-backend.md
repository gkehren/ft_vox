# Game UI and Developer UI

Proposed in #299 for maintainer review before production backend work in #300. This ADR selects the direction and defines the boundaries for the opt-in spike.

## Decision

Build the player UI as a bounded native C++20 layer over SDL3 and the existing Vulkan renderer. Keep Dear ImGui as the Developer UI. The player layer owns screen, layout, style and focus state and produces ordered, clipped draw batches. Engine remains the host of both layers. Reuse the frame, allocation, shader compilation and retirement facilities already in the repo.

The hardest graphics requirements are integration with the existing swapchain, atlas reload, frame fences and SDR output. Even with a UI library, the game would still own those integrations and its session-aware navigation and input policy. The native route has a real maintenance cost for layout, text editing and accessibility. Keep the layout to rows, columns, grids and scrolling, and put text measurement and shaping behind an interface. Reopen the decision if general document layout, complex-script authoring, or production controls exceed the budget below. RmlUi is the fallback to prototype in that case.

Versions are the evaluated upstream releases, with no imported source or packages. The RmlUi audit used upstream [6.3 release notes](https://github.com/mikke89/RmlUi/releases/tag/6.3), [license inventory](https://github.com/mikke89/RmlUi/blob/6.3/readme.md#license), [CMake options](https://github.com/mikke89/RmlUi/blob/6.3/CMakeLists.txt), [SDL/Vulkan sample](https://github.com/mikke89/RmlUi/blob/6.3/Backends/RmlUi_Backend_SDL_VK.cpp) and [HarfBuzz sample](https://github.com/mikke89/RmlUi/tree/6.3/Samples/basic/harfbuzz). Nuklear was evaluated from the [4.13.4 release](https://github.com/Immediate-Mode-UI/Nuklear/releases/tag/v4.13.4) and [upstream feature and license documentation](https://github.com/Immediate-Mode-UI/Nuklear/blob/v4.13.4/README.md).

The spike uses the repo-pinned ImGui 1.91.9 WIP source only to bake an independent copy of embedded ProggyClean glyphs on the CPU, plus a generated color sample. Dear ImGui and ProggyClean are MIT-licensed. The font source and attribution are in [imgui_draw.cpp](../../src/imgui/imgui_draw.cpp) and the library license is in [LICENSE.txt](../../src/imgui/LICENSE.txt). The spike owns its GPU atlas and uses its own draw pipeline, style and focus state. It adds no asset or package downloads. #302 will select and audit a production face. Any later shaping dependency must have an immutable version, license notices and a graphics-scoped build review before adoption. Graphics-off configures and links without any UI library.

## Ownership and input

- **Engine** publishes a frame-scoped, immutable presentation model made of bounded player, inventory, session, roster, save/host status and settings views. Use the existing sim and network snapshots and presentation helpers. Shared fields can also feed Dev UI. Renderer/camera handles, mutable settings, Vulkan handles and debug telemetry stay in renderer or developer adapters. The current mixed `GameUIFrame` serves legacy ImGui during migration.
- **Game UI** owns navigation and transient widget state. Root is Main Menu without a session, HUD during a session and Loading during a transition. The stack adds Pause, Inventory, Settings, Host/Join and authorized administration screens, plus confirmation/error modals above them. Restore focus to a surviving opener on pop. Loading, leave, reconnect, projection resets and profile/world changes clear transient gestures and invalidate stale results by session epoch. Errors offer the existing retry, recovery or return path.
- **Typed actions** carry values such as `SelectHotbar(slot)`, `MoveStack(from, to)`, `OpenWorld(name, seed)`, `Connect(JoinRequest)`, `StartHost(Options)` and `SetVSync(enabled)`. An Engine-owned adapter validates context and dispatches at the existing frame boundary or queues actions for an existing safe point. Each intent uses one path to solo simulation, remote command queues, settings or the hosting supervisor. Keep authoritative acknowledgments and failures, including stale or rejected inventory and admin results. UI drag state is presentation only and local-only administration still uses verified capabilities. A UI screen cannot mutate inventory, server roles or world state directly.
- **Developer UI** owns ImGui docking, panel visibility, debug settings and `imgui.ini`. It becomes opt-in with F1 after parity. Engine retains simulation pause and cursor ownership. Developer mode can coexist with live gameplay. Docking keeps the existing central scene viewport when active, while player HUD anchors to the actual scene viewport (full window with Dev UI closed). A full-window Game UI modal temporarily suppresses developer drawing and input and restores the developer layout on dismissal.
- **One input router** handles application/window events first, then explicit globals, the top player modal or interactive screen, active developer widgets, and finally gameplay. A modal may veto view-changing globals. Global shortcuts are non-repeating and explicitly enumerated. A passive HUD never claims gameplay input. Pointer press fixes its owner through release, and only eligible key edges reach gameplay. Focus loss or ownership/capture changes cancel presses, transient drags and queued jumps, reset relative mouse deltas and require held gameplay inputs to release before rearming. Text entry, wheel and Escape each go to one owner. Escape dismisses the top modal/screen or opens Pause from HUD. Quit remains explicit. Solo pause uses the host suspension policy. Multiplayer menus suppress local controls while networking and server simulation continue.

## Frame and lifetime

Record `scene → post → Game UI → Dev UI → present` on the graphics command buffer that Engine hands to WorldRenderer. Load the post color, use a positive viewport for top-left UI coordinates, intersect nested clips and clamp to the framebuffer before emitting scissors. Preserve the offscreen scene route as UI-free. Re-query logical window size and display scale separately from swapchain pixels, skip empty/minimized extents and use the same geometry transform for hit testing and paint. Player UI scale/accessibility preferences will be independent of developer layout preferences.

Use sRGB-authored UI colors/textures, decode RGB for linear blending and keep coverage alpha linear. An sRGB attachment does the output transfer. The spike uses opaque colors and glyph cutouts, and can write encoded RGB directly on the UNORM fallback. #300 must preserve linear-light Game UI blending on UNORM as well, using a linear SDR composition target and a final encode if needed. Keep legacy ImGui on its current target/transfer contract until separately validated. Validate the sRGB and UNORM paths with known swatches and edge coverage.

The graphical UI renderer owns GPU font and UI atlas resources and bounded descriptor sets. World item icons are borrowed via generation-tagged texture handles resolved by the renderer, with stable item IDs in the model. Publish complete replacements between frames. Retire old buffers, views and descriptors after their last referencing fence, before destroying the underlying image. Batch by texture and scissor in paint order. Frame-local vertices/indices or instances may be written only after `VkFrameContext` waits that slot's fence. Swapchain recreation rebuilds a format-dependent pipeline at the existing idle barrier and resizes using the new extent. Device teardown uses the existing idle barrier. Texture reload or resize must not introduce steady-state queue/device idle calls or descriptor updates to a set in use.

## Verification and budgets

- Keep layout, navigation, action mapping and input ownership in plain C++ with no SDL/Vulkan/ImGui link in CPU-only tests. Inject font metrics and normalized window/pointer events. Cover fit, scissor intersection, 16:9/21:9, logical-to-pixel transform and scale change, keyboard traversal and activation, modal priority, focus/drag cancel, epoch changes, one-shot actions and solo/network outcomes. Reuse `InventoryUi`, `InputRouting`, `UiScale` and `MultiplayerUi` policies where their contracts apply. Prefer replayable deterministic inputs.
- #300 onward targets on the canonical physical GPU at 1920×1080, after warmup over 600 frames with identical seed, camera, VSync and scene settings. Measure p95 player UI build + record on CPU and timestamp delta on GPU with Dev UI closed. HUD targets ≤0.25 ms CPU, ≤0.20 ms GPU and ≤8 draws. Inventory/menu targets ≤0.50 ms CPU, ≤0.35 ms GPU and ≤32 draws. Record the device, driver, swapchain format, medians, p95 and draw counts.
- Bound player UI allocations to ≤1 MiB host upload per frame slot, ≤8 MiB per live owned atlas generation and ≤64 live UI descriptor sets including retired generations. Validate that repeated resizing, failure-atomic pack/scale reload and screen navigation reach a stable allocation plateau. Track shared scene atlas memory separately. Require zero steady-state UI GPU readbacks, waits or descriptor allocations. These are acceptance targets for later phases, with no new mandatory GPU CI.
- The #299 spike only tests the frame hook, one clipped texture sample, button, text, focus and resize. It is available from `ft_vox --seed 42 --ui-spike` and Escape closes the preview. A normal launch opens the legacy UI. The spike's input and draw code can be removed together when #300 takes over. See [migration and evidence](../game-ui-migration.md).

Player UI work covers the existing game flows. Full localization, platform accessibility certification, full controller support, generalized document/CSS layout, public hosting, renderer redesign and gameplay, save or wire changes are outside this epic.
