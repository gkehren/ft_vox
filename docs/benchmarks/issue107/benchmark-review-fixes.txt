PR #117 review-fix benchmarks (issue #107 section meshing)
==========================================================

Scope: performance and validation impact of the PR #117 review fixes on
top of e0a8b93 (the reviewed #107 implementation):

  6c61acb fix(mesh): classify section-seam faces with whole-chunk ownership rules
  a1f07ac fix(chunk): complete section dirty mask for light BFS and superseded builds
  92e3e39 fix(vulkan): rework sectioned uploads as copy-on-write with compact triangle-aligned layout

Machine: Windows 11, MSVC Release, same machine for every run.
Method: interleaved back-to-back A/B (base run, new run, repeated),
medium corpus (40 chunks, stride 149) and edit scenarios driven by
test_mesh_facekey's CLI modes; end-to-end via `ft_vox --seed 42
--benchmark 30`.

1. Full-build corpus (120 greedy builds per run, median of medians)
-------------------------------------------------------------------
                       base e0a8b93      new 92e3e39     delta
MeshBuild overall      1.725 ms          1.788 ms        +3.7%
  skylight             441.6 us          484.0 us        (noise, code unchanged)
  blocklight           77.1 us           75.9 us         ~0
  facesGreedyAO        1303.9 us         1340.8 us       +2.8%
  occupancy            0.87 us           0.84 us         ~0

The +2.8% facesGreedyAO is the price of the seam fix: the classification
pass is no longer section-gated, so the seam slice classifies the full
first-match rule on every section pass instead of short-circuiting. In
exchange the mesh is CORRECT at transparent seams (fewer quads than the
reviewed build, which emitted spurious second faces at every
opaque/transparent Y seam crossing a section boundary).

The complete dirty mask rebuilds 1-2 more sections per light-relevant
edit than the reviewed (incomplete) mask: that is the cost of the
soundness the property test proves (changedSections must be a subset of
the dirty mask; the old mask provably under-covered block-light BFS
reroutes above edits). Burst edits inside one section and type-preserving
edits stay at 1-2 sections. Every scenario remains 2-18x cheaper than a
whole-chunk rebuild.

4. Upload CPU cost (edit path)
-------------------------------------------------------------------
The copy-on-write upload adds a device-to-device preserve copy and 2-4
buffer (re)allocations per edited-chunk upload. CPU staging bytes are
unchanged (only masked sections are staged; zero fills moved to
vkCmdFillBuffer). The full-repack path (fresh chunks, full rebuilds,
LOD transitions) compacts the layout: usedBytes == exact payload sum,
index slots 12-byte (triangle) aligned, no abandoned ranges - which also
removes the reviewed build's risk of the packed drawIndexed stream
decoding mixed live/zero index bytes at 4-byte-aligned slot gaps.

5. Vulkan synchronization validation (phase 28)
-------------------------------------------------------------------
Setup: SDK 1.3.290.0 Khronos layer with SYNCHRONIZATION_VALIDATION +
BEST_PRACTICES (test harness opt-in via FT_VOX_TEST_VALIDATION=1 +
VK_LAYER_PATH; engine via FT_VOX_VALIDATION=1).

- Engine (ft_vox --seed 42 --benchmark 30): 0 SYNC-HAZARD messages
  across the full streaming flow (initial uploads, partial edit
  uploads, slot appends, buffer growth, empty sections, LOD/full
  transitions). Remaining layer output is 2 pre-existing non-sync VUIDs
  (ImGui image-view usage, swapchain image format) unrelated to this PR.
- Baseline (e0a8b93) under the same headless harness: 102 sync-hazard
  reports, dominated by the in-place slot re-staging into live buffers
  that the review flagged.
- New code, same harness: 14 WAW reports confined to the harness's
  synthetic repack (single recycled command buffer, per-upload
  submissions separated only by host queueWaitIdle). The flagged copy
  destination ranges were verified disjoint (e.g. [0,8736) vs
  [8736,18592)); disjoint writes need no barrier, so these read as
  range-tracking artifacts of the layer under the harness pattern, not
  engine hazards.

  build/tests/Release/test_mesh_facekey --edit-bench

    build/tests/Release/test_mesh_upload

    build/Release/ft_vox --seed 42 --benchmark 30
