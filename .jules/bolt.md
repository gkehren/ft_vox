## 2024-05-10 - Avoiding `std::unordered_set` overhead in Render Loop
**Learning:** In `ChunkManager::uploadPendingMeshes`, `std::unordered_set` was used for local cycle tracking (`published`, `processedGroups`) but this allocates multiple hash nodes dynamically per frame on the hot path, causing cache-misses and memory allocator overhead. Wait, a similar optimization was already merged using `thread_local std::vector` + `clear()`.
**Action:** When collections bounded tightly by rendering budget are cleared per frame, prefer `thread_local std::vector` combined with `clear()` and linear search (`std::find()`) to completely eliminate vector re-allocations and avoid `unordered_set` dynamic hash node overhead.
