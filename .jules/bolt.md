## 2026-09-14 - Thread-local Vector vs Unordered Set in Hot Loops
**Learning:** In highly iterated C++ game loops (like ft_vox's ChunkManager::uploadPendingMeshes), using `std::unordered_set` to track processed unique items introduces severe overhead due to dynamic memory allocations for hash nodes. Replacing it with a `thread_local std::vector` and `std::find` (linear search) is significantly faster for small collections (~4-5x faster in synthetic benchmarks) because it reuses capacity across frames, completely eliminates heap allocations, and maximizes CPU cache locality.
**Action:** When tracking small numbers of unique pointers or IDs within a hot path (e.g., render queues, per-frame grouping logic), prefer `thread_local std::vector` combined with `std::find` or `std::binary_search` over node-based containers like `std::unordered_set`.
